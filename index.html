System Mechanics

How It Works (Under the Hood)

An event-driven orchestration pipeline engineered for concurrency safety, anti-detection evasion, and state persistence.

1

Job Dispatch & Atomic Task Claiming

When a task is submitted via Web UI or automated scheduler, it lands in the database as pending. Standalone worker threads poll the queue and execute an atomic update query:

UPDATE panel_bottask SET status='running' WHERE id=:id AND status='pending'

This eliminates SQLite double-dispatch race conditions across multiple daemon processes or threads.

2

Pre-Flight Proxy Validation & Routing

Before launching a browser instance, the task worker queries the proxy pool and evaluates handshake health. Any proxy classified as IG Blocked (HTTP 429/403) or Offline is omitted. Only verified Clean / Fast proxies are attached to Playwright's network stack.

Playwright Proxy Config: http://user:pass@host:port
3

Stealth Playwright Chromium Execution

Playwright launches Chromium or system Chrome with deep stealth flags. Automation indicators like --disable-blink-features=AutomationControlled are removed, navigator.webdriver = undefined is enforced, and keystrokes are dispatched with natural human jitter.

human_behavior.py: type_with_delay(selector, text, min_ms, max_ms)
4

Cookie Storage State & Clean Teardown

Successful sessions persist their full browser context storage states into session_cookies/{account_id}.json. Future engagement jobs reuse this storage state, skipping login checks. All resources, contexts, and pages are closed inside nested try...finally scopes to prevent zombie processes.

context.storage_state(path=f"session_cookies/{account.id}.json")
Architecture Roadmap

💡 Suggested Upgrades

High-value architectural recommendations to scale the repository into an enterprise commercial-grade SaaS platform.

High Scalability

1. Celery + Redis Distributed Queue

Transition from database thread polling to a distributed Celery message broker backed by Redis or RabbitMQ. Enables horizontal scaling across multiple VPS worker nodes with dedicated priority queues.

Impact: Run 1,000+ simultaneous browser jobs across distributed nodes.
Anti-Detection

2. Fingerprint & Canvas/WebGL Spoofing

Integrate specialized anti-detect libraries (or headless integration with Dolphin{anty} / AdsPower) to randomize Canvas 2D hashes, WebGL vendor strings, AudioContext, and WebRTC leaks.

Impact: Decreases Instagram account challenge rates by >70%.
Security

3. Native 2FA (TOTP / pyotp) Support

Incorporate a totp_secret schema in accounts to automatically solve two-factor authentication prompts when sessions expire, and lock created accounts with 2FA to prevent bans.

Impact: Zero checkpoint lockouts when session cookies expire.
AI Integration

4. LLM-Powered Contextual Comments

Integrate OpenAI / Claude / local Ollama models to inspect target post captions and image descriptions, generating human-like, unique, context-aware comments rather than generic spam strings.

Impact: Immune to Instagram's repetitive text spam filters.
Network

5. 4G/5G Mobile Proxies & Webhook Rotation

Add support for mobile rotating proxies with dynamic IP change URLs (rotation webhooks) that trigger an automatic carrier IP refresh between account switches.

Impact: Legitimate cellular carrier trust score; zero IP bans.
Commercial

6. Standard SMM Reseller REST API

Expose a standardized API via Django REST Framework compatible with reseller platforms (PerfectPanel, JustAnotherPanel) for automated order submission, balance checking, and status webhooks.

Impact: Turn this repository directly into a monetizable B2B SMM provider.
Deployment

🚀 Quick Start in 60 Seconds

Get the complete web dashboard and background queue worker running locally or in Docker.

bash — 1-click docker deployment
# 1. Clone the repository
$ git clone https://github.com/pain-hub/instagram_smm_panel.git && cd instagram_smm_panel
# 2. Spin up Docker containers (Django web + Playwright worker)
$ docker compose up -d --build
# 3. Access the dashboard & stream logs
✔ Web Dashboard ready at: http://localhost:8000
✔ Monitor worker logs: docker compose logs -f
